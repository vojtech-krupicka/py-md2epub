# md2epub

CLI that builds EPUB 2.0.1 publications from a YAML/JSON manifest plus Markdown chapters. Published on PyPI as
`markdown2epub`; the repo, the CLI command and the import package are all `md2epub`. Python 3.12+, managed with `uv`.

## Commands

```bash
uv sync --extra dev --extra docs     # run this first; a bare `uv run` recreates .venv WITHOUT the extras
uv run pytest --cov                  # CI form; fails under 90% coverage (plain `uv run pytest` skips coverage)
uv run ruff check .
uv run pip-audit
uv run bandit -r md2epub/
uv run mkdocs build --strict         # `mkdocs serve` to preview
```

## Layout

- `md2epub/models/public/` - the manifest models (`Book`, pages, metadata, config). Every field takes
  `Field(**docs.<name>)` from `docs.py`; the schema, Swagger page and docs are generated from these.
- `md2epub/processors/` and `core/` - turn a `Book` into EPUB content; `templates/` holds the built-in Jinja files.
- `md2epub/utils/templator.py` - Jinja rendering. `utils/utils.py` - `safe_join`, `safe_entry_name`.
- `docs/` - MkDocs source. `docs/manifest-reference/` is generated by `md2epub schema`; CI regenerates it, so
  don't hand-edit it.

## Branches and releases

- `main` is the released state and is protected (PR plus a passing `test` check). Work goes to `dev` (via feature
  branches), is batched, then one `dev` -> `main` PR is merged and tagged.
- A release is a GitHub Release, which runs `publish.yml` (PyPI Trusted Publishing, gated by the `pypi` environment).
- The version comes from the first `## [x.y.z]` heading in `CHANGELOG.md`; add the date when tagging. The sdist
  must include `CHANGELOG.md` (see `MANIFEST.in`) or wheels built from it get version 0.0.0.
- PyPI metadata is frozen per version, so README or `pyproject.toml` fixes only reach PyPI with the next release.

## Conventions

- Line length 120; ruff rules E, F, I. Keep bandit clean (`# nosec` only with a reason).
- Write `EPUB` in prose and comments. `ePUB` appears only inside the logo wordmark.
- README is also the PyPI long description: use absolute URLs for images and links, never relative paths.
- Verify GitHub Action versions through the GitHub API before pinning; don't guess tags.

## Security model

A manifest and its Markdown are untrusted input. Keep these intact:

- Every path from the manifest goes through `safe_join` and stays inside its manifest's folder.
- All Jinja runs in `SandboxedEnvironment` with autoescape on.
- Chapter HTML is sanitized with nh3.
- Markdown extensions are allow-listed; anything else needs `--trust-extensions`.

Known gap: custom page templates can't `{% extends %}` the built-in layout, and `{% include %}` follows symlinks out
of the project. Both are tracked for a fix in `utils/templator.py`.
